# Code Review Instructions

## Component: ocp-release-operator-sdk (Operator SDK downstream)

This is a **downstream mirror** of upstream `operator-framework/operator-sdk`. Most source code originates upstream — review focus should be on downstream-specific changes.

## Review Priorities

### Critical (block merge)
- Downstream patches in `patches/` must apply cleanly: `make -f ci/prow.Makefile patch`
- Build tag `containers_image_openpgp` must be present on all new Go build/test commands
- `vendor/` must stay in sync: `go mod tidy && go mod vendor` if dependencies change
- `UPSTREAM-VERSION` must match the merged upstream tag after a rebase
- No direct edits to upstream source — use the `patches/` mechanism

### Important (strong recommendation)
- Builder image Go version pins in `.ci-operator.yaml` and `release/helm/Dockerfile` must be consistent (note: `.ci-operator.yaml` uses `release-` prefix tag, Dockerfile does not)
- Version stamps in `Makefile` (`IMAGE_VERSION`, `K8S_VERSION`) must be consistent
- Generated files (`testdata/`, `doc/`, `internal/bindata/olm/`) regenerated with `make generate`

### Informational (nice to have)
- Patch naming follows sequential numbering convention
- Commit messages follow `<subsystem>: <what changed>` format

## Do Not Report

These are CI-enforced or generated — do not flag in reviews:
- `testdata/**` — generated by `make generate`
- `doc/**` — generated CLI documentation
- `vendor/**` — vendored dependencies
- `go.sum` — auto-generated
- `internal/bindata/olm/**` — generated OLM bindata
- `.cncf-maintainers` — generated
- `website/**` — upstream documentation site (git submodule)

## Path-Specific Rules

### `patches/`
- Verify patch applies: `make -f ci/prow.Makefile patch`
- Check patch targets still exist in upstream source
- Prefer minimal patches — avoid touching files unnecessarily

### `release/helm/`
- Dockerfile changes affect the shipped Helm Operator image
- Builder and base image references must use `registry.ci.openshift.org` paths
- Entrypoint scripts in `release/helm/bin/` are copied to the final image

### `hack/auto-rebase.sh`
- This runs as a Prow periodic with elevated credentials
- Changes must handle `DRY_RUN=1` correctly
- Error handling must be defensive — script runs unattended

### `ci/`
- `prow.Makefile` changes affect downstream CI builds
- Test scripts in `ci/tests/` are CI entrypoints
